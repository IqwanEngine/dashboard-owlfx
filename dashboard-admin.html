Standard Operating Procedure (SOP) Aliran Rekod OWLFX Ecosystem

Panduan rasmi pengendalian rekod pendaftaran klien bermula dari portal pendaftaran sehingga pengesahan akhir (clearance) oleh pihak BDM. Sila patuhi turutan aliran kerja (workflow) ini untuk memastikan data sentiasa selaras dan tiada kekeliruan status.

1 1. Pendaftaran Klien Baru (Client Registration Portal)
  • Portal URL: https://www.owlfx.my/daftar
  • Klien melengkapkan pendaftaran akaun trading dengan mengisi maklumat peribadi (Nama, No. Telefon, Emel, No. Akaun Trading MT5, dan broker yang dipilih).
  • Sebaik sahaja borang dihantar, data klien disimpan secara automatik ke dalam database Supabase (clients table).
  • Rekod baharu akan terus muncul secara langsung (real-time) di Dashboard Admin dengan status awal:
    Status Master: Pending Action Status: New / Submit to BDM
2 2. Semakan & Penetapan Skim di Dashboard Admin
  • Admin log masuk ke Dashboard Admin dan menyemak rekod klien yang baru masuk.
  • Admin menetapkan skim rebat yang bersesuaian melalui pilihan dropdown skim:
    Kategori STP: STP VIP 16$ | STP IB 14$ | STP Client 11$
    Kategori Booster: Booster VIP 20$ | Booster IB 18$ | Booster Client 14$
    Kategori Khusus: No Self Rebate
  • Paparan Remark BDM: Kolum remark di paparan Admin adalah bersifat read-only (plain text) tanpa gangguan dropdown bagi memaparkan catatan terkini dari BDM secara bersih dan tepat.
  • Pindaan Admin (Inline Edit): Sekiranya Admin perlu mengemas kini sebarang butiran atau catatan klien, klik butang Edit pada baris rekod tersebut. Menyimpan catatan teks biasa akan mengekalkan status sebagai Pending.
3 3. Pemprosesan di Dashboard BDM (Clearance Desk)

Pegawai BDM (VT Market Clearance Desk) membuka dashboard-bdm.html untuk memproses senarai klien berstatus Pending.

Pada kolum Remark / Action, BDM mempunyai dua mod tindakan utama:

A. Mod Catatan Bebas (Type Custom Remark):
  • Pilih mod dropdown: [ Type Custom Remark ].
  • Taip sebarang nota atau status semasa secara bebas (contoh: "Waiting submission IC", "Ada error dokumen", "Follow up deposit").
  • Klik butang [ Update ].
⚠️
Peraturan Utama (Guardrail): Rekod akan KEKAL DALAM STATUS PENDING. Tindakan ini tidak akan menutup tiket atau menandakan tugas selesai, memastikan kedua-dua pihak sedar tindakan susulan masih diperlukan.
Tarikh dan masa kemas kini pada ACTION / TIMESTAMP akan diperbaharui serta-merta.
B. Mod Pengesahan Selesai (Complete):
  • Pilih mod dropdown: [ Complete ].
  • Butang tindakan akan bertukar menjadi [ Complete ] (Emerald Green).
  • Klik [ Complete ] hanya setelah akaun klien disahkan sepenuhnya di sistem broker.
  • Status master akan bertukar secara rasmi kepada Completed bersama lencana pengesahan tarikh dan masa.
4 4. Penyelarasan Real-Time (Database Auto-Sync)
  • Setiap kemas kini rekod (teks catatan, pertukaran status, atau cap masa) disimpan secara terus ke database clients di Supabase.
  • Sebarang catatan atau perubahan status oleh BDM akan disiarkan secara langsung (real-time broadcast) ke dashboard Admin tanpa memerlukan muat semula halaman (no page refresh).
  • Kolum Update Date menyediakan jejak audit (audit trail) yang tepat bagi setiap pengubahsuaian rekod.
5 5. Kawalan Keselamatan Pemadaman Rekod (Record Deletion)
  • Butang Delete hanya digunakan bagi rekod ujian (testing), pendua (duplicates), atau pendaftaran tidak sah.
  • Sistem dilindungi oleh On-Screen Confirmation Modal ("Permanently Delete Client?").
  • Pengesahan diperlukan sebelum rekod dipadamkan secara kekal daripada database Supabase.
